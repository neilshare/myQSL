# myQSL 第二阶段关键测试与发布验收矩阵

日期2026-09-05；基线v1.0.0/5bdcffa；此文是待执行测试规格，不是测试通过报告。本轮只完成设计，没有模拟真机/外部邮箱发送成功。

配套：[技术设计](2026-09-05-myqsl-v1.1-v1.2-design.md)、[任务计划](../plans/2026-09-05-myqsl-v1.1-v1.2-implementation.md)。测试路径相对项目根 `/Users/zhangneil/WorkBuddy/HAM/eqsr`。

## 1. 测试层级与证据要求

- 纯逻辑：Vitest验证字节解码、领域映射、尺寸计算、状态归并，expected由协议/手工独立计算生成，不能复制实现结果。
- 数据集成：Cloudflare测试运行时使用真实本地D1迁移、R2、Workflow行为，覆盖并发/部分失败；只有mock service返回200不证明原子性。
- 本地代理：Node24真实loopback UDP与临时SQLite，kill/reopen、网络超时、容量/权限错误；同时保留synthetic和脱敏实机fixture标签。
- 浏览器：Playwright运行现有Web及新增路由，测试生成下载、权限、选择集合、取消和错误；固定浏览器/字体版本。
- 外部边界：QRZ/Resend先fake contract后授权账号自测；无凭据时允许开发继续，但相应发布项保持未验证。
- 印刷：独立PDF解析、字体检查、QR解码、栅格图对比和真实尺测；PDF可打开不等于合格矢量稿。

除标注观察项外，下列项目都是所属功能发布门禁。失败必须提供实际输入、预期、输出、运行器版本、trace/request_id；不要只写“测试失败”。环境启动失败需修复重跑，不能记为业务通过。
